# Medicity on Android

The web app is installable as a PWA and is also wrapped with
[Capacitor](https://capacitorjs.com) so it can ship on Google Play. The
native project lives in [`android/`](../android) (generated by `npx cap add android`
and committed); the web code stays in [`frontend/`](../frontend).

Items marked **TODO(owner)** need an account, a secret, or a decision that
cannot be made from the repository. Nothing in the repo contains a secret.

## 1. What is already done

| Piece | Where |
|---|---|
| Web app manifest (name, theme `#0b6f62`, standalone, maskable icon) | `frontend/public/manifest.webmanifest` |
| Icons 192 / 512 / maskable 512 / Apple touch, Android launcher + splash | `frontend/public/icons/`, `android/app/src/main/res/` (regenerate with `npm --prefix frontend run icons`) |
| Offline-shell service worker (never touches `/api`, `/ws`, non-GET, cross-origin) | `frontend/public/sw.js`, registered by `frontend/src/lib/registerServiceWorker.ts` |
| Capacitor config (`appId` `com.medicity.app` placeholder, API URL via env) | `frontend/capacitor.config.ts` |
| Android project: permissions, `allowBackup=false`, no cleartext, release signing hook | `android/` |

The service worker caches only the HTML shell, icons and the content-hashed
`/assets/*` files, none of which hold personal data. Offline, signed-in screens
show their normal "could not load" states rather than stale patient data. It is
not registered inside the Android shell, where the files are already local.

## 2. Prerequisites

- Node 22+ (Capacitor 8), JDK 21, Android Studio (or just the Android SDK with
  platform 36 and build-tools; set `ANDROID_HOME`).
- A deployed API on **https** (Railway today). Plain `http` is refused by the app.
- The API must allow the shell's origin: add `https://localhost` to
  `MEDICITY_CORS_ORIGINS` on the backend (this also covers the video-visit
  WebSocket, which reuses that list). Without it every call from the app fails
  with a CORS error.

## 3. Build and run

All commands from the repo root. `VITE_API_BASE_URL` is baked in at build time;
inside the app a relative `/api` has nowhere to go, so always set it.

```bash
npm --prefix frontend ci

# Debug on an emulator or a USB-connected phone
VITE_API_BASE_URL=https://medicity-production.up.railway.app \
  npm --prefix frontend run android:run

# Open in Android Studio instead
VITE_API_BASE_URL=https://medicity-production.up.railway.app \
  npm --prefix frontend run android:sync
npm --prefix frontend run android:open
```

Live reload against the dev server (emulator only, never for release):
`CAP_SERVER_URL=http://10.0.2.2:5173 npx --prefix frontend cap run android`.

If `android/` is ever lost, recreate it with
`npm --prefix frontend run build && (cd frontend && npx cap add android)` and
re-apply the edits to `AndroidManifest.xml`, `app/build.gradle` and
`.gitignore` shown in this repo's history, then `npm --prefix frontend run icons`.

## 5. Signing with Play App Signing

Play re-signs what users download with a key Google holds (the app signing key).
You sign the upload with an **upload key** you hold; if it is ever lost or
leaked, Google can reset it, which is why this arrangement is required for new apps.

1. **TODO(owner): create the upload keystore** (keep it and its passwords
   in a password manager, outside the repo):

   ```bash
   keytool -genkeypair -v -storetype PKCS12 -keystore ~/medicity-upload.jks \
     -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```

2. **TODO(owner):** create `android/keystore.properties` (git-ignored; `*.jks`,
   `*.keystore` and this file are all in `android/.gitignore`):

   ```properties
   storeFile=/home/you/medicity-upload.jks
   storePassword=...
   keyAlias=upload
   keyPassword=...
   ```

   `app/build.gradle` signs the release bundle with it when the file exists;
   without it the bundle is built unsigned.
3. In Play Console, create the app, then **Setup > App signing** and accept
   Play App Signing on the first upload. In CI, keep the same four values as
   secrets and write the file at build time; never commit them.

## 7. Policy items found in this codebase that need an owner decision

- **Account deletion is missing.** Play requires apps that let people create an
  account to offer in-app deletion *and* a web link for requesting it. The API
  has no delete-account endpoint today (`grep` of `AuthController` and the
  patient controllers). **TODO(owner):** build it (backend, outside the scope of
  this change), then fill in "Delete account" in Data safety.
- **Privacy policy:** none exists in the repo. **TODO(owner):** publish one at a
  public URL that names the processors in the next section.
- **Medical disclaimer / regulated-app rules:** Medicity connects patients with
  doctors and pharmacies, so complete the Health apps declaration honestly, and
  check local rules for e-pharmacy and telemedicine in the regions you list.
- **Push notifications** are not wired. **TODO(owner):** create a Firebase
  project, add `google-services.json` to `android/app/` (the Gradle file already
  applies the plugin when it is present), install `@capacitor/push-notifications`,
  add the `POST_NOTIFICATIONS` permission to the manifest, and add a backend
  endpoint to store device tokens. The in-app notification page works without it.
- **Media permissions at runtime:** the manifest declares camera, microphone and
  location. Capacitor's WebView asks the user when the web page requests them
  (video visit, "use my location", photographing a prescription). Test each on a
  real device with the permission denied, and on Android 14+.
- **WebRTC calls** use Google's public STUN server by default
  (`medicity.video.ice-servers`); a TURN server is needed for callers behind
  strict mobile networks. Not an Android-specific change, but expect failures on
  carrier NAT without one.

## 8. Data safety worksheet

Built from the code and API as of this change (`frontend/src`, controllers and
Flyway migrations V1 to V35). "Collected" in Play's terms means sent off the
device; "shared" means transferred to a third party (service providers that
process data only on your behalf are *not* "sharing", but must be named in the
privacy policy). Re-check against the code before every release.

General answers:

- Data encrypted in transit: **Yes** (HTTPS only; `usesCleartextTraffic=false`).
- Users can request deletion: **No today. See section 7; change to Yes once built.**
- Data collected is required or optional: see each row.
- Advertising / analytics SDKs: **none in the app.** No ad id is read.
- No data is collected by the app code itself beyond what the user enters or
  what the device features below provide. Session tokens live in the app's
  private WebView `localStorage` (`medicity.access`, `medicity.refresh`) and are
  excluded from Android backup (`allowBackup=false`).

| Play data type | What Medicity actually collects | Source | Required? | Purpose | Shared? |
|---|---|---|---|---|---|
| **Personal info > Name** | Full name (patients, doctors, chemists, family members) | Register / profile | Required | App functionality, account management | No |
| **Personal info > Email address** | Account email, sign-in codes by email | Register, login | Required (or phone) | Account management, app functionality | No (sent through Resend as processor) |
| **Personal info > Phone number** | Phone for SMS sign-in; emergency contact number | Register, profile | Optional | Account management, app functionality | No (MSG91 as processor) |
| **Personal info > Address** | Home address line and city; doctor clinic address; chemist store address | Profile, practice, store | Optional (patients); required for doctors and stores | App functionality | Doctors' and stores' addresses are shown publicly to patients |
| **Personal info > Other info** | Date of birth, gender, relationship of family members, medical council and registration number (doctors), drug licence number (chemists) | Register, profile | Required for those roles | App functionality, verification | No |
| **Personal info > User IDs** | Internal account UUID, role | Server | Required | Account management | No |
| **Health and fitness > Health info** | Blood group, height, weight, allergies, chronic conditions, current medications, symptoms and "since when" in the pre-visit intake, reason for visit, doctor's diagnosis (ICD-10), prescriptions and dosage, dispensing and pickup records, visit notes, follow-up questions and answers, courses of medicine | Health profile, booking, doctor workspace, pharmacy | Optional for the patient; created by doctors for visits | App functionality | Prescription requests are sent to verified chemists the patient chooses; a handwritten-prescription photo is processed by Anthropic and/or Google (Gemini) for reading |
| **Location > Approximate location** | Coordinates from "use my location" used to find chemists within 3 km | Device GPS via browser API | Optional | App functionality | No |
| **Location > Precise location** | Same GPS fix, stored as the patient's home latitude and longitude; a doctor's clinic pin; a chemist's store coordinates | Profile, practice, store, medicine requests | Optional (patients) | App functionality | Doctor and store pins are public. Each "ask chemists nearby" request stores the patient's coordinates with a search radius; check what the chemist screens display before answering "shared" |
| **Photos and videos > Photos** | Photos of handwritten prescriptions (camera capture), uploaded images of reports | Camera / file picker | Optional | App functionality | Prescription photos go to the AI reader (Anthropic / Google) and to the chemist the patient sends the request to |
| **Files and docs > Files and docs** | PDFs and images attached to a visit (reports, referrals) | File picker | Optional | App functionality | Visible to the treating doctor |
| **Audio > Voice or sound recordings** | Live microphone audio during a video visit. Peer to peer, **not recorded or stored by the server** | Microphone | Optional (only when joining a video visit) | App functionality | No (carried peer to peer; Google STUN sees the device IP) |
| **Photos and videos > Videos** | Live camera video during a video visit, same handling | Camera | Optional | App functionality | No |
| **App activity > App interactions / Other user-generated content** | Appointments, queue tokens, waitlist entries, medicine requests and reservations, reviews and ratings of doctors, messages in follow-ups, notifications and read state | Throughout | Required for the feature used | App functionality | Reviews are shown to other patients |
| **App info and performance** | None collected (no crash reporter or analytics SDK) | n/a | n/a | n/a | n/a |
| **Device or other IDs** | **IP address** is stored in the audit log with security-relevant actions (login, booking, record changes); no advertising ID, no device ID. Capacitor adds no identifier | Server | Required (security) | Fraud prevention, security, compliance | No |
| **Financial info** | None. Consultation fee is shown, payment is not processed in the app | n/a | n/a | n/a | n/a |
| **Contacts / Calendar / SMS / Call log** | None | n/a | n/a | n/a | n/a |
| **Web browsing / Search history** | Doctor and specialty searches are sent to the server to return results; not stored as history | Doctors page | n/a | App functionality | No |

Security practices block (the Console asks): encrypted in transit **yes**;
deletion mechanism **TODO(owner)** (section 7); Play Families / independent
security review **no**; follows Play Families policy **no (18+)**.

Processors to name in the privacy policy: Railway (hosting) and the database
host, Resend (email codes), MSG91 (SMS codes, when enabled), Anthropic and
Google Gemini (reading handwritten prescriptions, when enabled), Google
(STUN for video calls), Vercel (web hosting).
